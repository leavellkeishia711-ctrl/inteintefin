## Название стадии

### **Stage 1 — "Financial Core"** (Финансовое ядро)

Кодовое имя фазы: **`core`**.

Это фундамент, на который встанет всё остальное. Мы сознательно **не** трогаем Market Intelligence, парсинг Telegram, коннекторы ко всем рекламным API и собственную нейросеть — всё это самое сложное, рискованное (в т.ч. юридически) и, главное, **не является ядром ценности**. Собственный roadmap проекта прямо советует отложить MI на Фазу 3–4.

**Ценность, которую даёт эта стадия сама по себе:** владелец медиабаинговой компании впервые видит **одну честную цифру** — сколько компания реально заработала и на сколько дней хватит денег. Это продаётся и без AI-разведки.

---

## Принцип сужения

| Отложено (не в MVP) | Почему |
|---|---|
| **Market Intelligence целиком (§5.7)** — включая MI-lite | Самый рискованный модуль (скрейпинг, юридика, human review). **Аддендум v2.6 отменил MI-lite полностью**: промежуточной ручной версии не будет. Модуль появляется сразу правильным на Stage 4a. |
| Все рекламные/трекер-коннекторы сразу | Каждый коннектор — отдельный проект (rate limits, нормализация, валюты, атрибуция). В MVP — ручной ввод + CSV + опционально 1 коннектор. |
| Собственная нейросеть на своём сервере | Дорого и преждевременно. Стартуем на внешних AI API. |
| Модераторские роли, Human Review Queue | Отложены целиком вместе с MI (Stage 4a). В MVP нет AI-контента из внешних источников, поэтому модерировать нечего. |
| Forecasting Engine, Scenario Modeling, Recommendation Engine | Post-MVP. В MVP — только простые детерминированные метрики (Cash Runway = доступный баланс / средний дневной расход). |
| Team Performance Analytics | Post-MVP. |

## Что входит в MVP (scope)

### 1. Аутентификация и мультитенантность
- Регистрация / вход (email + пароль, Argon2id).
- Приглашения сотрудников (`invites`) с ограниченным сроком действия.
- Компания = tenant. Каждый пользователь принадлежит компании.
- **Изоляция данных между компаниями — обязательна на уровне запросов** (каждый запрос фильтруется по `company_id`). Это критично для SaaS с финансами.
- Роли: `owner`, `cfo`, `team_lead`, `media_buyer`, `farmer`, `processor`, `creative`.

> ⚠️ **Security note:** любой endpoint, отдающий финансовые данные, должен проверять принадлежность к `company_id` из сессии, а не принимать `company_id` из запроса. Отсутствие этой проверки = утечка чужих финансов.

### 2. Учёт транзакций и мультивалютность
- Ручное добавление доходов/расходов.
- Категории (реклама, зарплаты, инфраструктура, налоги, подрядчики, партнёрские выплаты, прочее).
- **CSV-импорт** транзакций с возможностью отката по `import_batch_id`.
- **Мультивалютность:** сумма + валюта на каждой транзакции + курс `fx_rate_to_base` на дату операции. Таблица `fx_rates`. Хранение в `decimal`.

### 3. Financial Dashboard (§5.1)
- Revenue, Expenses, Profit, Margin (%), Cash Balance, EBITDA.
- ROI / ROAS (считаются, когда есть данные по кампаниям).
- **Cash Runway** — ключевая метрика: `доступный баланс / средний дневной расход`.
- **Finance Health Score** — простая агрегированная формула: `0.4 * MarginScore + 0.4 * RunwayScore + 0.2 * TrendScore` (ограничено 0..100).

### 4. P&L Management (§5.2)
- Отчёт доходы/расходы за период.
- Разбивка по категориям для вычисления Gross Profit, EBITDA, EBIT, EBT, Net Profit.

### 5. Cash Flow Management (§5.3)
- Движение денег во времени (по датам транзакций).
- Остаток на начало/конец периода.
- Учёт партнёрских выплат (отслеживание статусов Booked -> In Hold -> Scrubbed -> Paid) и ожидаемой/фактической суммы.
- Liquidity Health / Cash Runway (запас прочности рассчитывается строго из **доступных** средств на балансе, игнорируя деньги в холде).

### 6. Расходники (Consumables)
- Учёт карт, прокси, сервисов. Привязка к рекламному аккаунту и транзакциям для P&L (EBITDA).
- Хранятся только маскированные идентификаторы.

### 7. Заливы (Campaign Runs)
- Единица работы байера: кто, когда, какой аккаунт, `spend`/`revenue` за период. Итоги считаются через ежедневную статистику `campaign_run_stats`.

### 8. Расчёт зарплат (Payroll)
- Автоматизированный расчёт выплат (`payroll_run`, `payroll_line_items`) на основе базовой ставки и бонусного процента/квоты.
- Поддержка модели оплаты для роли "обработчик" (processor): фикс + ставка за подтверждённый лид (piece rate).
- Поддержка статуса `held` при финансовых рисках.

### 9. AI Financial Analyst — базовый (§5.6)
- Диалоговый ассистент **только на внутренних данных** компании.
- Отвечает на «почему изменилась прибыль/ROI» на основе загруженных транзакций и кампаний.
- Реализация через внешний AI API. **Без модерации** — данные принадлежат самой компании.

> ⚠️ **Security note:** в промпт AI попадают только данные компании текущего пользователя. Не допускать утечки данных других тенантов в контекст модели.

### 10. Alerts — базовый (§5.14)
- Только на внутренних метриках: `Cash runway < 30 дней` (порог настраивается), `ROI ниже порога`.
- Защита от спама (`dedup_key`, `cooldown_until`).

### 11. Data Quality Monitoring — базовый (§5.15)
- Отметка «данные не обновлялись N часов» или «давно не было транзакций».

### 12. Telegram-бот — исходящий
- **Единый бот** на весь продукт (не по одному на компанию).
- Привязка аккаунта через токен из веба (`telegram_link_tokens`) → сохраняется в `telegram_chat_id`.
- Функции: доставка алертов + запрос личного статуса (свой spend, свой заработок, свой ROI, статус зарплаты/бонуса).
- **Только исходящие сообщения и личные запросы.** Никакого чтения чатов, никакого парсинга — это Stage 4a.

### 13. Audit Log — базовый (§5.11)
- Логирование изменений транзакций/бюджетов: кто, что, когда, IP, Request ID.

### 14. Локализация (i18n)
- Поддержка языков на уровне компании и пользователя (EN, RU).

### 15. Опционально (stretch, если останется время): 1 read-only коннектор
- Один трекер или один рекламный кабинет. Только чтение spend/revenue. Если не успеваем — переносим в Фазу 2.

## Что НЕ входит в MVP (явный список)

- ❌ **Market Intelligence в любом виде** — ни автосбор, ни ручная форма внесения источника (MI-lite отменён).
- ❌ Собственная нейросеть на своём сервере.
- ❌ UI модерации и роли модератора.
- ❌ Полный набор коннекторов.
- ❌ Forecasting Engine (сложный), Scenario Modeling, Recommendation Engine.
- ❌ Team Performance Analytics.
- ❌ Budget Planning с AI-проверкой ликвидности.

## Definition of Done для MVP

1. Пользователь может зарегистрировать компанию и пригласить сотрудников с ролями (через систему `invites`).
2. Данные компаний строго изолированы (проверено тестами на межтенантный доступ).
3. Можно загрузить транзакции вручную и через CSV (с `import_batches`).
4. Dashboard показывает Revenue / Expenses / Profit / Margin / Cash Balance / Cash Runway / EBITDA.
5. P&L и Cash Flow формируются за выбранный период.
6. Отработана мультивалютность (`fx_rates` и `fx_rate_to_base`).
7. AI Financial Analyst отвечает на вопросы по внутренним данным. **Обязательное условие:** ответ сгенерирован через tool use с реальным запросом к БД.
8. Работают алерты по Cash Runway и ROI с защитой от дублирования.
9. Все действия с финансами пишутся в Audit Log.
10. Деньги везде в `decimal`, потери копеек нет.
11. Учёт расходников (consumables): привязываются к аккаунту, стоимость попадает в EBITDA.
12. Заливы фиксируются как `campaign_runs`, статистика собирается через `campaign_run_stats`.
13. Автоматизирован расчёт зарплат (`payroll_runs`).
14. Telegram-бот: сотрудник безопасно привязывает аккаунт к `telegram_chat_id` и получает личный статус и адресные алерты.
15. Есть автотесты на финансовые расчёты и на изоляцию тенантов; проект собирается и проходит тесты.
16. Работает базовая поддержка i18n.

## Рекомендованный порядок реализации (внутри MVP)

```
1.  Каркас проекта + БД + миграции + auth + i18n
2.  Модуль приглашений (invites) и ролевая модель
3.  Модель валют (fx_rates) + мультитенантность
4.  Модель транзакций + ручной ввод + CSV-импорт (с batch_id)
5.  Рекламные аккаунты + расходники (consumables)
6.  Заливы (campaign_runs) + ежедневная статистика (campaign_run_stats)
7.  Расчёт зарплат (payroll_runs)
8.  Расчётный слой: P&L (EBITDA), Cash Flow, Cash Runway, ROI/ROAS
9.  Financial Dashboard (UI поверх расчётного слоя)
10. Audit Log (пронизывает изменения из шагов 4–8)
11. Alerts (Cash Runway, ROI) + email + дедупликация
12. Telegram-бот: безопасная привязка, личный статус, доставка алертов
13. AI Financial Analyst (внутренние данные, обязательный tool use)
14. Data Quality Monitoring (базовый)
15. (stretch) 1 read-only коннектор
```
