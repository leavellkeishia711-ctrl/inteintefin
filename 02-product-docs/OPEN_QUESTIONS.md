## ⛔ Критические риски — обязательны к соблюдению

> Этот раздел — НЕ открытые вопросы. Здесь зафиксированы решения, нарушение которых создаёт критический риск для продукта. Они не обсуждаются — они соблюдаются.

### CR-1. AI Analyst: обязательный tool use с реальными данными

**Риск:** если AI Analyst отвечает на вопросы о финансах без обязательной привязки к реальным данным через tool use (function calling), продукт будет генерировать уверенно звучащие, но **выдуманные** финансовые объяснения. Для финансового инструмента это **худший возможный сбой** — хуже, чем отсутствие фичи вообще, потому что пользователь может принять реальное бизнес-решение на основе выдуманных цифр.

**Решение (принято, не подлежит пересмотру):**
- Каждый ответ AI Analyst формируется через цепочку: вопрос → модель решает, какие инструменты вызвать (`get_pnl`, `get_cash_flow`, `get_campaign_performance` и т.д.) → бэкенд выполняет SQL-запросы к PostgreSQL → реальные цифры возвращаются модели → модель формирует ответ **только** на основе полученных данных.
- Прямой вызов модели без этого шага **не допускается ни в каком виде**, даже как временное решение для MVP.
- Definition of Done для модуля AI Analyst в `MVP.md` содержит явное условие, блокирующее приёмку без tool use.

**Почему это здесь, а не в «Открытых вопросах»:** это не вопрос, а зафиксированный инвариант. Риск — в случайном **регрессе** при рефакторинге, смене модели или добавлении новой фичи.

## Как пользоваться этим файлом

1. Открытый вопрос закрывается → переносится в таблицу «Уже решено» с обоснованием.
2. Перед стартом каждой стадии `ROADMAP.md` — проверить, что связанные с ней вопросы решены.
3. Критические риски (раздел ⛔) **никогда не переносятся в «Решено»** — они остаются как постоянные инварианты.
4. Новые развилки добавляются сюда, а не теряются в переписке.
