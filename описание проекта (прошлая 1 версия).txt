# FinanceIntel — контекст проекта для AI-ассистента

## Что это
SaaS финансового управления и «финансовой разведки» для медиабаинговых
компаний и арбитража трафика. Работает ПОВЕРХ трекеров и рекламных
кабинетов, не заменяет их. Роль продукта — виртуальный CFO: собрать все
доходы и расходы (реклама, зарплаты, инфраструктура, расходники, налоги)
и показать реальную картину бизнеса.

Позиционирование:
- Трекер (Keitaro/Voluum/Binom): «какая реклама приносит деньги?»
- FinanceIntel: «что происходит с бизнесом, почему и что делать дальше?»

Слоган: «От цифр к решениям».

## Целевые роли пользователей
owner/CEO, CFO, team_lead, media_buyer, farmer, processor, creative, admin.
(moderator / compliance появятся только на Stage 4.)

## Текущая стадия: Stage 1 — «Financial Core»
В скоупе MVP:
1. Auth + мультитенантность (компания = тенант, жёсткая изоляция по company_id)
2. Транзакции: ручной ввод + CSV-импорт, мультивалютность, категории
3. Financial Dashboard: Revenue, Expenses, Profit, Margin, Cash Balance,
   ROI/ROAS, Cash Runway, Finance Health Score
4. P&L по периодам и категориям
5. Cash Flow + партнёрские выплаты (booked → in_hold → scrubbed → paid), скраб
6. Рекламные аккаунты + расходники (прокси, карты) с попаданием в P&L
7. Заливы как отдельная сущность campaign_runs (единица работы байера)
8. Payroll: base_salary + bonus_percent, квоты фармеров, payroll_runs
9. AI Financial Analyst — только на внутренних данных компании
10. Alerts (cash runway, ROI) на email + единый Telegram-бот (исходящий)
11. Audit Log, базовый Data Quality Monitoring

НЕ в MVP (не предлагать и не реализовывать):
- Market Intelligence в любом виде (парсинг Telegram/форумов, лента сигналов,
  Impact Briefs, human review queue, роли модератора) — это Stage 4a/4b
- Полный набор коннекторов Meta/Google/TikTok/Voluum/Binom/Affise — Stage 2
  (в MVP максимум 1 read-only коннектор, кандидат Keitaro, и то опционально)
- Forecasting Engine, Scenario Modeling, Recommendation Engine, Team
  Performance Analytics — Stage 3/5
- Собственный инференс-сервер / своя модель — отложено

## Роадмап
Stage 1 Financial Core (сейчас) → Stage 2 Data Connectors →
Stage 3 AI Analytics & Forecasting → Stage 4a/4b Market Intelligence →
Stage 5 Decision & Scale. Каждая стадия = продаваемый срез продукта.

## Стек
- Backend: FastAPI (Python), Celery, Redis
- БД: PostgreSQL
- Frontend: Next.js (App Router), React, TailwindCSS, Recharts
- AI: внешние API (OpenAI/Anthropic), обязательный function calling / tool use

## Жёсткие инварианты (нарушать нельзя)
1. Деньги ВСЕГДА NUMERIC(20,4). Никогда float. Валюта хранится рядом с суммой.
2. Время — TIMESTAMPTZ (UTC). Везде created_at/updated_at, soft-delete
   через deleted_at.
3. company_id берётся ИЗ СЕССИИ, никогда из тела запроса. Любой endpoint
   с финансовыми данными проверяет принадлежность тенанту. Иначе — утечка
   чужих финансов.
4. CR-1: AI Analyst отвечает ТОЛЬКО через tool use с реальным SQL-запросом
   к БД (get_pnl, get_cash_flow, get_campaign_performance и т.п.). Прямой
   вызов модели без данных запрещён даже как временное решение.
5. В контекст LLM попадают данные только текущего тенанта.
6. Реквизиты карт/прокси не хранятся. Только маскированный идентификатор
   (последние 4 цифры / host) — иначе попадаем под PCI DSS.
7. Секреты и токены шифруются, не логируются, не идут в AI-контекст.
8. Идемпотентность импорта: UNIQUE (company_id, source, external_id).
9. ROI/ROAS/margin/EBITDA — вычисляемые, в БД не хранятся.

## Ключевые формулы
Gross Profit = revenue − ad_spend
EBITDA       = gross_profit − (salary + infra + other + consumables)
EBIT         = EBITDA − depreciation
Net Profit   = EBIT − interest − tax
ROI          = (revenue − spend) / spend * 100
ROAS         = revenue / spend
Cash Runway  = cash_balance / avg_daily_spend
               (только доступные средства, деньги в холде НЕ считаются)

## Дизайн-система (globals.css, Tailwind @theme)
Семантические токены поверх CSS-переменных, есть light и .dark:
  background #f8fafc / surface #ffffff / border #e2e8f0
  content-primary #0f172a, secondary #475569, tertiary #94a3b8
  primary (teal): 50 #f0fdfa · 500 #14b8a6 · 600 #0d9488 · 700 #0f766e
  ai (indigo): 50 #eef2ff · 500 #6366f1 · 600 #4f46e5  ← только для AI-блоков
  success / warning / danger — тройками bg + text + border
  font-sans Inter, shadow-card мягкая двойная тень
Правило: цвета брать из токенов (bg-surface, text-content-secondary,
border-border), а не хардкодить. Часть экранов это правило нарушает
(bg-red-50, text-gray-600 напрямую) — при доработке приводить к токенам.
Тёмная тема описана в CSS, но переключателя в UI нет.

## Адаптивный UI по составу команды
staffing.tsx: StaffingProvider держит Record<StaffRole, boolean> в
localStorage (ключ financeintel.staffing.v1). Хелперы has(role) и
компонент <IfRole role="farmer">. Если роли в компании нет — раздел под
неё не рендерится. На реальном бэкенде источник = COUNT(*) по users,
группировка по staff_role внутри company_id.
Роли: media_buyer (обязательная), team_lead, farmer, processor, creative.
Это производственная роль (staffRole), она НЕ равна role в users
(права доступа: owner/cfo/team_lead/...).

## Справочники (constants.ts)
VERTICALS (с marketShare), HIGH_RISK_VERTICALS = igaming/crypto/nutra,
GEOS (с tier), PLATFORMS, PAYOUT_MODELS, PAYMENT_TERMS, STAFF_ROLES

## /api/chat — намеренная заглушка
Роут НЕ генерирует фейковые AI-ответы: возвращает текст «бэкенд не
подключен» на нужной локали. Это соблюдение инварианта CR-1. Не
заменять на моковую генерацию ответов ни при каких условиях. Правильная
доработка — проксировать на FastAPI /api/v1/chat с tool use.
