# Большой план проекта (новая версия v3) — FinanceIntel после Stage 1

## 1. Executive Summary
FinanceIntel — SaaS финансового управления и аналитики для медиабаинговых команд. Stage 1 (Financial Core) полностью реализован и прошел Staging тестирование. Продукт находится в статусе PRODUCTION BLOCKED по причине отсутствия валидного интеграционного тестирования инфраструктуры Linux/Docker с параллельной нагрузкой. Переход к Stage 2 возможен после прохождения production-gate.

## 2. Product Vision
Создание "виртуального CFO", способного поверх трекеров автоматически агрегировать доходы, расходы, выплаты партнерам, рассчитывать payroll, отслеживать метрики ROI/ROAS и Margin, а также предоставлять AI Analyst для финансового анализа данных.

## 5. Architecture
- FastAPI, Python, SQLAlchemy 2.0, PostgreSQL 16, Alembic, RLS, Redis, Celery, Next.js 16, React 19, TypeScript, Tailwind, next-intl, TanStack Query.

## 6. Data model and invariants
- Деньги хранятся через Decimal/NUMERIC, float в финансовых расчётах запрещён.
- Финансовые таблицы используют soft delete там, где это предусмотрено схемой.

## 7. Security model
- company_id не должен приниматься из body, query или аргументов LLM, а берётся из JWT/session context.
- PostgreSQL RLS и tenant context являются обязательными слоями изоляции.
- Сырые секреты, токены, полные данные карт и пароли не хранятся и не попадают в LLM-контекст.

## 8. AI Analyst policy
- обязательный tool use;
- успешный tool call обязателен перед финальным ответом;
- корректный Anthropic `tool_use`/`tool_result` flow;
- продолжение цикла после успешного инструмента;
- neutral error для LLM;
- отсутствие traceback, SQL и внутренних деталей в LLM;
- whitelist payload;
- защита от IDOR через ad_account_id/campaign_run_id;
- tenant isolation.

## 9. Alerts and Telegram
- webhook secret validation;
- one-time link token;
- expiry and reuse protection;
- user and tenant scoping;
- `/link`;
- `/status`;
- Redis rate limiting;
- fail-closed для `/link` при Redis outage;
- best-effort in-memory fallback только для некритичных операций.

## 12. Production blockers
PRODUCTION BLOCKED.
Причины:
1. Не выполнен обязательный Linux/Docker Compose прогон.
2. Не подтверждён запуск PostgreSQL 16, Redis 7, двух backend workers, Celery worker и Celery Beat в Linux/Docker.
3. Не выполнен целевой Linux-нагрузочный тест asyncpg/SQLAlchemy pool.
4. Локальный Windows-тест не является заменой Linux production-gate.

## 16. Definition of Done for Production
Успешное прохождение интеграционных и нагрузочных тестов (asyncpg/SQLAlchemy, Redis outage) на нативной среде Linux/Docker Compose с минимум двумя воркерами Uvicorn и чистой базой данных, без утечек секретов и дедлоков event loop.

## 17. Risks and assumptions
- Запуск PostgreSQL/asyncpg под реальной конкурентной нагрузкой не подтверждён в целевой ОС.
- Деградация Redis outage при нескольких worker’ах в Linux не протестирована.
